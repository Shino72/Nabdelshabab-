# نبض الشباب: منصة إخبارية عربية متكاملة

موقع إخباري كامل (واجهة عامة + لوحة تحكم + قاعدة بيانات + نظام إعلانات + واجهة API) باللغة العربية واتجاه RTL. يعمل على **Vercel + Supabase** بدون خادم خاص، أو على أي خادم Node.js مع PostgreSQL.

---

## 1. التقنيات وسبب اختيارها

| الجزء | التقنية |
|---|---|
| الخادم والواجهة | Node.js 22 (عرض الصفحات من الخادم SSR) |
| قاعدة البيانات | PostgreSQL على Supabase (الاعتمادية الوحيدة: مكتبة `pg`) |
| الصور | Supabase Storage (أو مجلد `uploads` عند التشغيل على خادم بدون Supabase) |
| الاستضافة | Vercel (دالة واحدة تستقبل كل الطلبات) أو أي خادم Node.js |
| الخطوط | Noto Kufi Arabic للعناوين وNoto Naskh Arabic للنصوص (رخصة SIL OFL المفتوحة) |

**لماذا هذا الاختيار؟**
- **بدون خادم تديره:** Vercel يشغّل الموقع، وSupabase يحفظ البيانات والصور بشكل دائم، والاثنان لهما خطط مجانية.
- **سرعة:** الصفحات تُبنى على الخادم وتُرسل مضغوطة، ولا تعتمد على JavaScript ثقيل في المتصفح، وهذا مهم لمحركات البحث وللموبايل.
- **اعتماديات أقل:** حزمة خارجية واحدة فقط (`pg`)، فالتحديث بسيط وسطح الثغرات صغير.

**كيف يعمل الاتصال بقاعدة البيانات؟** كُتب الموقع أصلًا على SQLite بواجهة متزامنة. للإبقاء على كل المسارات والنماذج كما هي، تعمل الاستعلامات داخل Worker مستقل (`src/bridge.js`) وينتظر الخادم نتيجتها. كل الاستعلامات معاملات مُجهزة، والجداول تُنشأ تلقائيًا عند أول طلب، ومحمية بـ RLS فلا تُقرأ عبر واجهة Supabase العامة.

## 2. التشغيل المحلي

المتطلبات: **Node.js 22.13 أو أحدث** وقاعدة **PostgreSQL** (محلية، أو مشروع Supabase).

```bash
npm ci
cp .env.example .env
#    عدّل في .env: DATABASE_URL و SITE_URL=http://localhost:3000 و NODE_ENV=development و COOKIE_SECURE=false
npm start
```

افتح: `http://localhost:3000` للموقع، و`http://localhost:3000/admin` للوحة التحكم.

عند أول تشغيل تُنشأ الجداول تلقائيًا مع 40 مادة تجريبية، على كل منها علامة «تجريبي» (لا تُفهرس في محركات البحث، وتُحذف بضغطة واحدة من الإعدادات). لإيقافها: `SEED_DEMO=false`.

أوامر أخرى:

```bash
npm run dev            # تشغيل مع إعادة التحميل التلقائي عند تعديل الكود
npm test               # الاختبارات الآلية (تحتاج TEST_DATABASE_URL لقاعدة PostgreSQL يمكنها إنشاء قواعد بيانات)
npm run create-admin   # إنشاء حساب مدير أو إعادة تعيين كلمة المرور
npm run backup         # نسخة احتياطية من قاعدة البيانات (JSON)
```

## 3. إنشاء حساب المدير الأول بأمان

لا توجد أي كلمة مرور افتراضية داخل الكود. اختر إحدى الطريقتين:

**الطريقة المفضلة (سطر الأوامر):**
```bash
npm run create-admin
```
يطلب الاسم والبريد وكلمة المرور (تُكتب مخفية). كلمة المرور 10 أحرف على الأقل وتحتوي على حروف وأرقام.

**أو عبر متغيرات البيئة عند أول تشغيل** (الطريقة المناسبة على Vercel): ضع `ADMIN_EMAIL` و`ADMIN_PASSWORD` في متغيرات البيئة، افتح الموقع مرة واحدة، ثم **احذف `ADMIN_PASSWORD` فورًا**. يُنشأ الحساب فقط إذا لم يكن هناك مدير.

بعد الدخول:
1. غيّر بيانات الموقع من **إعدادات الموقع**.
2. أنشئ حسابات المحررين من **المستخدمون والصلاحيات**.
3. احذف المحتوى التجريبي قبل الإطلاق إن لم تعد تحتاجه.

نسيت كلمة المرور؟ شغّل `npm run create-admin` بنفس البريد لتعيين كلمة جديدة.

## 4. ما يتضمنه الموقع

### الواجهة العامة
- **الرئيسية:** الخبر الرئيسي، أهم الأخبار، آخر الأخبار بخط زمني، الأكثر قراءة، أقسام منفصلة، الرأي والتحليلات، التحقيقات، شريط الوسائط المتعددة.
- **شريط الأخبار العاجلة:** متحرك من اليمين بالشكل الصحيح للعربية، يتوقف عند المرور عليه، وفيه زر إيقاف، ويحترم إعداد «تقليل الحركة».
- **صفحات الأقسام:** 11 قسمًا مع ترقيم الصفحات.
- **صفحة الخبر:**
  - الكاتب وتاريخ النشر وآخر تحديث ومدة القراءة.
  - المصادر والوسوم، والمشاركة (واتساب، فيسبوك، إكس، تيليجرام، نسخ الرابط)، والطباعة.
  - أخبار ذات صلة، وتعليقات تخضع للمراجعة.
- **البحث:** بالعنوان والنص والوسوم، مع توحيد الهمزات والتاء المربوطة (البحث عن «إقتصاد» يجد «اقتصاد»)، والتصفية بالقسم والتاريخ.
- **التصفح:** أرشيف حسب اليوم والقسم، وصفحات للوسوم والكتّاب.
- **صفحات ثابتة:** من نحن (مع بيانات الإدارة)، اتصل بنا (نموذج رسائل)، أعلن معنا (أسعار + نموذج حجز)، سياسة الخصوصية، شروط الاستخدام، وصفحة 404.
- **العرض:** وضع ليلي ونهاري يتذكر اختيار الزائر، وتصميم متجاوب للموبايل والتابلت والكمبيوتر.
- **SEO:**
  - روابط واضحة لكل خبر (`/news/123/عنوان-الخبر`)، ووسوم Open Graph.
  - بيانات منظمة (NewsArticle وBreadcrumb وOrganization).
  - `sitemap.xml` و`news-sitemap.xml` و`robots.txt` و`rss.xml`.

### بيانات الإدارة
تظهر في التذييل وصفحة «من نحن»، وتُعدَّل من **الإعدادات ← بيانات الإدارة**:
- رئيس مجلس الإدارة: سيف خالد عامر
- تحت إشراف: دكتور فاطمة الزهراء
- تحت إشراف: دكتور حمدان
- وفي أسفل الموقع: «مشروع جامعي» (يتغير أو يُخفى من الإعدادات)

### لوحة التحكم (`/admin`)
- **المواد:**
  - إضافة وتعديل وحذف الأخبار والمقالات بمحرر فيه أزرار تنسيق ومعاينة حية.
  - رفع صور الغلاف ومعارض الصور وإضافة فيديو يوتيوب، واختيار القسم والنوع والكاتب.
  - مسودات، وإرسال للمراجعة، ونشر فوري، وجدولة للنشر لاحقًا، وأرشفة.
  - تثبيت الأخبار في الرئيسية.
- **الأخبار العاجلة:** مع وقت انتهاء تلقائي.
- **مكتبة الوسائط:** رفع وحذف، مع منع حذف صورة مستخدمة.
- **التعليقات والبلاغات:** موافقة ورفض وحذف، وإغلاق البلاغات.
- **رسائل «اتصل بنا».**
- **مصادر RSS:** جلب العناوين فقط إلى صندوق وارد، وتحويلها إلى مسودة. لا يُنشر شيء تلقائيًا أبدًا.
- **الإعلانات:**
  - حملات بتاريخ بداية ونهاية وبيانات المعلن، مع تفعيل وإيقاف.
  - تحديد المساحة، والتناوب بين أكثر من حملة في نفس المساحة.
  - احتساب الظهور والنقرات، وتقرير CSV لكل حملة.
  - إدارة المساحات وأسعارها، وطلبات الإعلان القادمة من صفحة «أعلن معنا».
- **التقارير:** الزيارات اليومية، أكثر المواد مشاهدة، المشاهدات حسب القسم، إنتاج الكتّاب، أداء الحملات.
- **الإدارة والإعدادات:**
  - المستخدمون والصلاحيات (4 أدوار).
  - إعدادات الموقع: الاسم والشعار والتواصل والسوشيال ونصوص الصفحات وبيانات الإدارة.
  - سجل نشاطات.

### الأدوار

| الدور | الصلاحيات |
|---|---|
| مدير عام | كل شيء |
| محرر (رئيس تحرير) | كتابة ومراجعة ونشر وجدولة كل المواد، العاجل، التعليقات، الرسائل، المصادر، التقارير |
| كاتب / مراسل | كتابة المسودات ورفع الصور وإرسالها للمراجعة فقط (لا ينشر مباشرة) |
| مسؤول إعلانات | الحملات والمساحات وطلبات الإعلان والتقارير |

### طريقة كتابة النص في المحرر
لأسباب أمنية لا يُقبل HTML داخل المقالات. بدلًا منه:

```
## عنوان فرعي
> اقتباس
- بند في قائمة
**نص غامق**
[نص الرابط](https://example.com)
![وصف الصورة](/uploads/2026/10/photo.jpg)
```

## 5. واجهة API (JSON)

**قراءة عامة (بدون تسجيل دخول):**
```
GET /api/v1/articles?category=sports&q=الدوري&page=1&per_page=20
GET /api/v1/articles/123
GET /api/v1/categories
```

**للمحررين:** تسجيل الدخول يعيد `csrf_token` وملف تعريف جلسة، ثم يُرسل الرمز في الترويسة `X-CSRF-Token` مع كل عملية كتابة.

```bash
# تسجيل الدخول وحفظ الجلسة
curl -c jar.txt -H "Content-Type: application/json" \
  -d '{"email":"admin@site.com","password":"..."}' https://example.com/api/v1/auth/login

# إضافة خبر ونشره
curl -b jar.txt -H "Content-Type: application/json" -H "X-CSRF-Token: <الرمز>" \
  -d '{"title":"عنوان الخبر","body":"نص الخبر","category_id":1,"tags":["وسم"],"action":"publish"}' \
  https://example.com/api/v1/admin/articles

# تعديل جزئي (الحقول غير المرسلة تبقى كما هي)
curl -b jar.txt -X PUT -H "Content-Type: application/json" -H "X-CSRF-Token: <الرمز>" \
  -d '{"title":"عنوان جديد"}' https://example.com/api/v1/admin/articles/45

# حذف
curl -b jar.txt -X DELETE -H "X-CSRF-Token: <الرمز>" https://example.com/api/v1/admin/articles/45
```

قيم `action` المتاحة: `draft` و`submit` و`publish` و`schedule` (مع `publish_at` بصيغة `2026-11-01T09:00` بتوقيت القاهرة) و`archive`. نفس الصلاحيات وقواعد التحقق المطبقة في لوحة التحكم.

## 6. النشر على الإنترنت

### الخيار (أ) Vercel + Supabase (موصى به، يعمل من الموبايل)

1. **Supabase:** أنشئ مشروع Supabase **منفصلًا** لنبض الشباب. لا تستخدم قاعدة بيانات موقع آخر: الموقع يرفض العمل فوق جداول تطبيق آخر ويعرض رسالة توضح ذلك.
   - أسهل طريقة: من Vercel ← مشروع nabdelshabab ← **Storage** ← **Create Database** ← **Supabase**، فتُضاف متغيرات الاتصال (`POSTGRES_URL` و`SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`) تلقائيًا.
   - أو يدويًا: أضف في Vercel ← Settings ← Environment Variables:
     - `DATABASE_URL`: من Supabase ← Connect ← **Transaction pooler** (المنفذ 6543) مع كلمة مرور قاعدة البيانات.
     - `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` (أو `SUPABASE_SECRET_KEY`): من Project Settings ← API. ضع المفتاح كـ **Secret**.
2. **متغيرات أخرى في Vercel:**
   - `ADMIN_EMAIL` و`ADMIN_PASSWORD` (كـ Secret) لإنشاء أول مدير، ثم احذف `ADMIN_PASSWORD` بعد أول دخول.
   - `SITE_URL` (اختياري): رابط الموقع النهائي. إن لم يُضبط يُستخدم رابط Vercel الأساسي للمشروع.
   - `SESSION_SECRET` (اختياري): إن لم يُضبط يُنشأ تلقائيًا ويُحفظ في قاعدة البيانات.
3. **المنطقة:** Vercel ← Settings ← Functions ← **Function Region**: اختر أقرب منطقة لمنطقة مشروع Supabase (مثلًا Frankfurt مع eu-central-1). كل صفحة تنفذ عدة استعلامات، والمسافة بينهما تؤثر على السرعة.
4. **Redeploy**، ثم افتح الموقع. أول طلب ينشئ الجداول، وقد يستغرق ثواني.
5. ادخل من `/admin/login`.

ملاحظات:
- الصور تُحفظ في مساحة `nabd-media` العامة في Supabase Storage (تُنشأ تلقائيًا عند أول رفع)، وروابطها على الموقع `/uploads/...` تحوّل إليها.
- Vercel يرفض الطلبات الأكبر من 4.5 ميجابايت، لذلك الحد الأقصى للصورة 4 ميجابايت، ومكتبة الوسائط ترفع الصور واحدة تلو الأخرى.
- الاتصال بقاعدة البيانات مشفّر. للتحقق من هوية خادم Supabase أيضًا: نزّل الشهادة من Project Settings ← Database ← SSL وضع محتواها في `DATABASE_CA_CERT`.
- خطة Vercel المجانية (Hobby) للاستخدام غير التجاري. انتقل لخطة مدفوعة قبل تشغيل إعلانات مدفوعة. مشاريع Supabase المجانية تتوقف مؤقتًا بعد أسبوع بدون زيارات.

### الخيار (ب) خادم VPS مع Docker وHTTPS تلقائي

`docker-compose.yml` يشغّل الموقع مع قاعدة PostgreSQL محلية وCaddy لشهادة HTTPS.

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-v2
git clone <مستودعك> nabd && cd nabd
cp .env.example .env && nano .env
#   SITE_URL=https://example.com
#   NODE_ENV=production
#   POSTGRES_PASSWORD=<حروف وأرقام>
nano deploy/Caddyfile                      # ضع الدومين الخاص بك بدل example.com
sudo docker compose up -d --build
sudo docker compose exec app node scripts/create-admin.js
```

لاستخدام Supabase بدل القاعدة المحلية: اضبط `DATABASE_URL` و`SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` في `.env` واحذف خدمة `db`.

### ربط الدومين
- **Vercel:** Settings ← Domains ← أضف الدومين واتبع سجلات DNS التي تظهر.
- **VPS:** من لوحة DNS أضف سجلي `A` للاسمين `@` و`www` بعنوان IP الخادم.

ثم حدّث `SITE_URL` بالدومين الجديد.

### الخيار (ج) Render.com أو خادم بدون Docker
- **Render:** New ← Blueprint ← اختر المستودع؛ يقرأ `render.yaml` ويطلب `DATABASE_URL` وبيانات Supabase. لا يحتاج قرصًا دائمًا لأن البيانات في Supabase.
- **بدون Docker:** ثبّت Node.js 22، انسخ المشروع إلى `/opt/nabd`، شغّل `npm ci --omit=dev`، ثم `deploy/nabd.service` مع `deploy/nginx.conf` و`certbot`.

### بعد النشر: قائمة تحقق
- [ ] الموقع يفتح على `https://` من الموبايل والكمبيوتر.
- [ ] `/admin` يحوّل إلى صفحة الدخول، والدخول يعمل.
- [ ] أضف خبرًا بصورة، ثم Redeploy وتأكد أن الخبر والصورة ما زالا موجودين.
- [ ] احذف `ADMIN_PASSWORD` من متغيرات البيئة.
- [ ] أضف `https://<الدومين>/sitemap.xml` في Google Search Console.

## 7. النسخ الاحتياطي والتحديث

```bash
# نسخة JSON من كل الجداول (يحتفظ بآخر 14 نسخة في مجلد backups)
DATABASE_URL=... npm run backup
```

الملف يحتوي بيانات حساسة (بصمات كلمات المرور ومفتاح التوقيع)، فاحفظه في مكان آمن. Supabase يأخذ نسخًا يومية في الخطط المدفوعة. الصور في Supabase Storage تُنزَّل من لوحة Supabase.

**تحديث الموقع لاحقًا:** ادفع الكود الجديد إلى GitHub فيعيد Vercel النشر تلقائيًا. تحديثات مخطط قاعدة البيانات تُطبَّق تلقائيًا عند أول طلب، والبيانات لا تُمس.

## 9. تقرير الاختبارات

تشغيل: `npm test`. **النتيجة: 47 اختبارًا ناجحًا من 47** على خادم حقيقي وقاعدة PostgreSQL مؤقتة (بترتيب نصوص en-US مثل Supabase). يغطي:

- **الواجهة العامة:**
  - فتح الرئيسية والتأكد من RTL وشريط العاجل وبيانات الإدارة.
  - فحص كل الروابط الداخلية في الرئيسية (أكثر من 40 رابطًا) بدون روابط معطلة.
  - كل الصفحات الثابتة وصفحة 404.
  - صفحة الخبر: تحويل الرابط الخاطئ للرابط الصحيح، والبيانات المنظمة، وأزرار المشاركة.
- **البحث والأرشيف:** البحث بالعربي مع توحيد الهمزات، والتصفية بالقسم، والأرشيف حسب التاريخ.
- **SEO:** ملفات sitemap وrobots وRSS.
- **الدخول والحماية:**
  - منع فتح لوحة التحكم وواجهة API بدون دخول.
  - رفض كلمة المرور الخاطئة، والدخول الناجح بجلسة HttpOnly.
  - رفض أي عملية بدون رمز CSRF.
  - تحديد محاولات الدخول، ومنع الوصول لملفات خارج المجلدات العامة.
- **إدارة الأخبار:**
  - إضافة خبر مع رفع صورة ونشره وظهوره في الموقع، مع منع XSS في العنوان والنص.
  - التعديل وانعكاسه، والمسودة تُخفي الخبر، والمعاينة، والحذف.
  - احتساب المشاهدات بدون تكرار.
  - الجدولة: الخبر لا يظهر قبل موعده، ورفض موعد في الماضي.
  - رسائل التحقق من المدخلات.
- **الصور:** رفض ملف مزيف بامتداد صورة، وقبول الصور الحقيقية.
- **الصلاحيات:** الكاتب لا ينشر ولا يفتح صفحات الإدارة، والمحرر يراجع وينشر، ولا يمكن إزالة صلاحية آخر مدير.
- **الإعلانات:**
  - ظهور الحملة في مساحتها، واحتساب الظهور والنقرات، والتحويل للمعلن.
  - تقرير CSV، والإيقاف والاستئناف، ورفض الروابط الخطيرة.
  - تعديل الأسعار وظهورها في «أعلن معنا»، ووصول طلب الحجز للوحة التحكم.
- **التفاعل:**
  - التعليقات بمراجعة قبل النشر، والإبلاغ، وحقل المصيدة ضد الرسائل الآلية.
  - رسائل «اتصل بنا».
  - الأخبار العاجلة، والإعدادات وانعكاسها على الموقع.
- **API واستيراد RSS:**
  - API العامة، وAPI المحررين: دخول، إضافة، تعديل جزئي، حذف، مع الحماية.
  - استيراد RSS من خادم اختبار محلي بدون نشر تلقائي.
- **الاستمرارية:** **بقاء الأخبار والصور والجلسات بعد إعادة تشغيل الخادم**، وحذف المحتوى التجريبي مع بقاء المحتوى الحقيقي.
- **التشغيل على Vercel وSupabase:**
  - الدالة المصدَّرة تنشئ الجداول والمدير عند أول طلب، وكل الجداول محمية بـ RLS.
  - رفع الصور إلى Supabase Storage (خادم محاكٍ) مع إنشاء المساحة تلقائيًا، وتحويل روابط `/uploads` إليها، وحذفها.
  - فشل التخزين يظهر كرسالة خطأ، ومحاولات الدخول تُحسب في قاعدة البيانات، وانقطاع الاتصالات الخاملة لا يُسقط الطلب التالي.
  - رسالة واضحة عند غياب `DATABASE_URL` أو عند ربط قاعدة بيانات تطبيق آخر (بدون تعديلها).
  - قراءة متغيرات Vercel وSupabase وإعدادات SSL.

**ما لم يُختبر هنا:** النشر الفعلي على Vercel والاتصال بمشروع Supabase حقيقي (يحتاجان حساباتك)؛ اتبع قائمة التحقق في القسم 6 بعد النشر.

**اختبار بصري:** فُتح الموقع في متصفح Chromium حقيقي:
- مقاسات كمبيوتر (1366 بكسل) وموبايل (390 بكسل)، بالوضعين النهاري والليلي.
- لا توجد أخطاء JavaScript، ولا تمرير أفقي على الموبايل.
- زر الوضع الليلي وقائمة الموبايل ونافذة مكتبة الوسائط ومعاينة المحرر تعمل.

## 10. ما يحتاج إعدادًا منك أو لم يُنفذ بعد

| البند | الحالة |
|---|---|
| النشر على رابط حقيقي | يحتاج ربط Supabase بمشروع Vercel (الخطوات في القسم 6) |
| الدفع الإلكتروني للإعلانات | **غير مفعّل**. حالة الدفع تُسجَّل يدويًا. يمكن لاحقًا ربط بوابة مثل Paymob أو Fawry أو Stripe بعد فتح حساب تاجر واختبارها |
| إشعارات البريد الإلكتروني (طلب إعلان أو رسالة جديدة) | **غير منفذة**؛ تظهر في لوحة التحكم مع عداد. تحتاج خدمة SMTP لتفعيلها لاحقًا |
| تصغير الصور تلقائيًا | **غير منفذ**؛ ارفع صورًا مضغوطة بعرض 1200 إلى 1600 بكسل، أو استخدم Cloudflare أمام الموقع |
| مصادر RSS | الآلية تعمل، لكن **استخدم فقط مصادر تسمح بإعادة الاستخدام** أو لديك اتفاق ترخيص معها |
| الخطوط | تُحمَّل من Google Fonts (رخصة OFL). للاستضافة الذاتية: ضع ملفات woff2 في `public/fonts` وعدّل الرابط في `src/views/layout.js` |
| سياسة الخصوصية والشروط | نصوص مبدئية قابلة للتعديل من الإعدادات؛ **يُنصح بمراجعتها قانونيًا** (مثلًا وفق قانون حماية البيانات الشخصية المصري) |
| اسم «نبض الشباب» | **تأكد من توفره** كدومين وعدم تعارضه مع علامات تجارية قائمة. الاسم يتغير من الإعدادات، وعند تغييره استبدل `public/img/og-default.png` (صورة المشاركة) |
| إحصاءات متقدمة | الإحصاءات الحالية من الخادم. يمكن إضافة Google Analytics لاحقًا (يتطلب تعديل سياسة CSP وتحديث سياسة الخصوصية) |
| Google AdSense | غير مدمج؛ النظام الحالي للإعلانات المباشرة. إضافة AdSense تتطلب تعديل CSP |

│   ├── feeds.js              جلب RSS مع الحماية من SSRF
│   ├── seed.js               الأقسام والمساحات الإعلانية والمحتوى التجريبي
│   ├── models/               استعلامات قاعدة البيانات

├── public/                   CSS وJavaScript والصور الثابتة

├── test/                     الاختبارات الآلية

ملفات لا ترفعها لأي مستودع:
- `.env`: الإعدادات السرية.
- `backups/`: النسخ الاحتياطية.
- `uploads/`: الصور عند التشغيل بدون Supabase Storage.

## 12. ملاحظات أمنية

- كلمات المرور مشفرة بـ scrypt مع salt عشوائي، والجلسات تُخزن مجزأة (hash) في قاعدة البيانات بملفات تعريف HttpOnly وSameSite.
- حماية CSRF على كل عمليات لوحة التحكم، وتحديد عدد محاولات الدخول.
- سياسة CSP صارمة تمنع تنفيذ أي سكربت غير معروف، وكل المحتوى يُهرَّب تلقائيًا في القوالب.
- الصور تُفحص من محتواها الفعلي (وليس الامتداد)، وتُحفظ بأسماء عشوائية، وملفات SVG مرفوضة.
- كل الاستعلامات معاملات مُجهزة (parameterized)، فلا مجال لحقن SQL.
- مفتاح الخدمة في Supabase (`SUPABASE_SERVICE_ROLE_KEY`) يبقى على الخادم فقط ولا يصل للمتصفح. ضعه في Vercel كـ Secret.
- الجداول محمية بـ RLS وصلاحيات anon محذوفة، فلا يمكن قراءتها بالمفتاح العام لـ Supabase.
- شغّل الموقع خلف HTTPS فقط، وخذ نسخًا احتياطية دورية.
